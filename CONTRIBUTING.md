# Контрибьюция

Спасибо за вклад в AntarktidaUI. Система должна оставаться предсказуемой для пользователей, разработчиков и AI-агентов.

## Перед изменением

1. Проверьте существующие токены, primitives, patterns и страницу `index.html`.
2. Для повторно используемого решения сначала определите API компонента, затем добавляйте его стили и пример.
3. Не меняйте бизнес-логику потребительского приложения в рамках задачи по дизайн-системе.

## Визуальные правила

- Используйте семантические переменные из `design-system/tokens/`; не добавляйте случайные цвета в компонент.
- Стройте размеры и отступы на четырёхпиксельной шкале, основной rhythm unit — 8 px.
- Проверяйте светлую и тёмную темы, узкий экран и состояния hover, focus, disabled, error.
- Для новых интерактивных паттернов обеспечьте клавиатурное управление, видимый фокус и понятные доступные имена.
- Не добавляйте декоративные эффекты, если они не улучшают навигацию или считывание данных.

## Проверка изменений

- Откройте `index.html` или запустите локальный сервер по инструкции в README.
- Если менялся JavaScript, проверьте синтаксис: `node --check design-system/interactions.js`.
- Убедитесь, что якоря документации ведут к существующим разделам.
- В описании pull request кратко перечислите изменение и способ проверки.

Не добавляйте framework или runtime в репозиторий без отдельной задачи: Twig-шаблоны сейчас служат integration API, а демонстрация работает как статический сайт.
